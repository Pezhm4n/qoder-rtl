# Qoder Persian RTL — راست‌چین‌سازی چت Qoder برای فارسی و عربی

دو روش برای اضافه کردن راست‌چینی، فونت **وزیرمتن** آفلاین و مدیریت صحیح متن دوجهته به محیط چت **Qoder** (اپ Electron مستقل، نه بر پایه VS Code):

| روش | چه می‌کند | وضعیت روی Qoder 0.3.3 |
|---|---|---|
| **`npx qoder-persian-rtl` — تزریق زنده با CDP** (پیش‌فرض، بی‌وابستگی) | هیچ فایل نصب را تغییر نمی‌دهد؛ پچ فقط داخل پروسهٔ در حال اجرا تزریق می‌شود | ✅ کار می‌کند |
| `qoder-rtl patch --yes` — پچ `app.asar` | سه فایل داخل آرشیو می‌نویسد (بکاپ + بازگردانی دارد) | ❌ روی این نصب Qoder بالا نمی‌آید (دلیلش پایین) |

## چرا «پچر» و نه «افزونه»؟

Qoder یک اپ Electron مستقل است؛ چت داخل همان renderer اصلی رندر می‌شود و سیستم پلاگین‌ها فقط `views` جدا و sandboxed می‌دهد که به DOM چت دسترسی ندارند. پس تزریق باید یا داخل خود renderer انجام شود (asar) یا از بیرون با پروتکل DevTools (CDP).

## روش ۱ — تزریق زنده (بدون دست‌زدن به نصب)

```bash
npx qoder-persian-rtl            # پیش‌نیاز: فقط Node.js — کلون، npm install و ساخت فایل لازم نیست
```

اگر Qoder در حال اجراست، همین‌جا وصل می‌شود و پچ را تزریق می‌کند؛ اگر بسته باشد، `npx qoder-persian-rtl start` اول خودش برنامه را با پرچم پورت دیباگ بالا می‌آورد. **مسیر CDP هیچ وابستگی‌ای ندارد**: `@electron/asar` از `dependencies` به `devDependencies` رفته (فقط روش ۲ به آن نیاز دارد)، پس آنچه دانلود می‌شود خودِ پکیج است (tarballِ اندازه‌گرفته‌شده با `npm pack --dry-run`: **۲۰۱٫۶KB** در ۱٫۱۰٫۰، ۳۸۸٫۹KB بازشده؛ فونتِ base64 داخل payload به همین‌جا اضافه می‌شود) نه ۶٫۸ مگابایت `node_modules`. اگر پورت 9222 روی ماشین شما گرفته باشد، `start` بی‌آنکه Qoder را اجرا کند رد می‌شود و می‌گوید **چه کسی** آن را گرفته (بخش «چهار حالت پورت» پایین‌تر). پیش‌فرضِ پورت را هم می‌توان عوض کرد: با `--port` یا متغیر محیطی `QODER_RTL_PORT`.

| دستور `qoder-rtl` | کار |
|---|---|
| `start` (بی‌نام = پیش‌فرض) | اتصال/راه‌اندازی + تزریق، و زنده نگه‌داشتن پچ تا `Ctrl+C` |
| `check` | تزریق + سنجشِ چهارده‌سطری + نوشتن گزارش در `%LOCALAPPDATA%\qoder-persian-rtl\cdp-test.log` |
| `diagnose` | فقط‌خواندنی: وضعیت واقعی هر پنجره در `cdp-diagnose.log` |
| `list` | پنجره‌هایی که CDP می‌بیند |
| `status` | نسخهٔ ابزار، نسخهٔ payload، نسخهٔ Qoder، **وضعیت واقعی پورت دیباگ** (نه فقط باز/بسته)، بودن/نبودن launcher، و این‌که مسیر آرشیو روی این ماشین در دسترس است یا نه |
| `launcher` | ساخت `Qoder-RTL.cmd` — **اختیاری** و فقط برای کسی که می‌خواهد با دابل‌کلیک شروع کند |
| `remove-launcher` | پاک کردن همان فایل‌هایی که `launcher` ساخته (چیزی در نصب Qoder دست نمی‌خورد) |
| `patch --yes` | روش ۲؛ عمداً پشت `--yes` قفل است و بی‌آن فقط توضیح می‌دهد چرا روی Qoder 0.3.3 اجرا نشود |

هر دستور همان موتور `live.js` را به‌صورت پروسهٔ فرزند اجرا می‌کند و کد خروج را پاس می‌دهد، پس `node cli.js check` دقیقاً همان `qoder-rtl check` است (اگر کلون کرده‌اید و نمی‌خواهید npx بزنید). گزینه‌های خودِ `live.js` هم دست‌نخورده‌اند:

```bash
node live.js --start --check     # Qoder بسته‌شده باشد: خودش با پورت باز می‌کند و نتیجه را می‌سنجد
node live.js                     # اتصال به Qoder در حال اجرا (پورت 9222) و پچ پنجره‌ها
node live.js --check             # فقط بررسی و نوشتن گزارش در cdp-test.log
node live.js --list              # پنجره‌هایی که CDP می‌بیند
```

| گزینه | معنا |
|---|---|
| `--port <n>` | پورت DevTools (پیش‌فرض `9222`؛ `QODER_RTL_PORT` همان کار را برای همهٔ دستوررها می‌کند و `--port` بر آن اولویت دارد) |
| `--wait <s>` | چند ثانیه منتظر باز شدن پورت بماند (پیش‌فرض ۳۰؛ `0` یعنی یک‌بار ببین و گزارش بده) |
| `--check` | تزریق + سنجش + خروج؛ نتیجه در `%LOCALAPPDATA%\qoder-persian-rtl\cdp-test.log` |
| `--diagnose` | فقط‌خواندنی: گزارش وضعیت واقعی هر پنجره (فونت محاسبه‌شده، CSP، مستطیل `.qrt-widget`) در `cdp-diagnose.log`؛ بدون تزریق |
| `--start` | راه‌اندازی Qoder با `--remote-debugging-port` (نیاز به بستن کامل Qoder؛ اگر پورت گرفته باشد یا حالِ Qoder قابل تشخیص نباشد **بلافاصله رد می‌شود** و توضیح می‌دهد چرا) |
| `--launcher` | ساخت `Qoder-RTL.cmd` هم کنار `live.js` و هم در `%LOCALAPPDATA%\qoder-persian-rtl` (پوشه AppData در ویندوز مخفی است) |
| `--remove-launcher` | پاک کردن همان دو فایل؛ چیزی از نصب Qoder حذف نمی‌شود |
| `--list` / `-v` | نمایش targetها / گفت‌وگوی تفصیلی |

پنجرهٔ کنسولِ injector باید باز بماند (`Ctrl+C` = قطع پچ) و اگر بخواهید خودتان Qoder را با پورت باز کنید، **همهٔ پنجره‌ها از جمله آیکون سینی** را ببندید: Qoder تک‌نسخه‌ای است، پس اگر نسخهٔ در حال اجرا باز باشد، راه‌اندازی تازه به همان پروسه واگذار می‌شود و پرچم `--remote-debugging-port` دور ریخته می‌شود. هیچ پروسه‌ای در این ابزار کشته نمی‌شود.

### چهار حالت پورت — «connect نشد» یعنی چه؟

قبلاً `start` بعد از ۶۰ ثانیه صبر فقط می‌گفت «چیزی روی 9222 گوش نداد» و یک علت حدسی چاپ می‌کرد؛ آن علت **غلط** بود (همان build در روزهای دیگر ۱۳/۱۳ سبز بوده). حالا `lib/cdp.js` حالت پورت را از خودِ ویندوز می‌پرسد و چهار جواب واقعی دارد:

| حالت | چطور سنجیده می‌شود | یعنی |
|---|---|---|
| `serving` | `GET /json/version` جواب می‌دهد | پورت باز است و CDP کار می‌کند |
| `free` | یک `net.Server` موقت روی همان پورت bind می‌شود | هیچ‌کس بگیرش ندارد؛ `start` می‌تواند اجرا شود |
| `occupied` + صاحب زنده | bind خطای `EADDRINUSE` می‌دهد، بعد `netstat -ano` و `tasklist` صاحب PID را نشان می‌دهند | یک برنامهٔ دیگر (مثلاً خودِ Qoder) پورت را دارد؛ `--port 9333` |
| `occupied` + صاحبِ رفته | همان بالا، ولی PID در `tasklist` نیست | **سوکت یتیم**: پروسه‌ای که پورت را باز کرده از بین رفته ولی listener جایش می‌ماند، پس هیچ Qoder تازه‌ای نمی‌تواند bind کند |

حالت آخر روی همین ماشین اندازه گرفته شد: `127.0.0.1:9222 LISTENING` با PID `9104` که دیگر وجود ندارد، در حالی که Qoderِ زنده (PID `15120`) با پرچم `--remote-debugging-port=9222` اجرا شده بود ولی روی آن پورت گوش نمی‌داد، و `DevToolsActivePort` برنامه در `Roaming\com.qoder.app.stable` هنوز همان 9222 را از ۰۲:۵۵ نوشته بود. `qoder-rtl status` همین را در یک سطر می‌گوید و راه‌حل می‌دهد (بستن کامل Qoder/ری‌استارت، یا یک پورت تازه). توجه: این توضیحِ **استخراج‌شده از اندازه‌گیری** است، بازسازیِ لحظه‌ی واگذاری پورت را هیچ اجراِ ثبت‌شده‌ای ندیده است.

دو گارد هم از همان منبع می‌آیند: اگر `tasklist` بخواهد جوابِ ناخوانا بدهد، ابزار آن را «Qoder اجرا نمی‌شود» تفسیر نمی‌کند و بی‌اطلاعی Qoder را اجرا نمی‌کند؛ و اگر پورت قبل از اجرا گرفته باشد، اصلاً launch نمی‌شود. پیامِ شکستِ `--start` هم حالا سه مشاهدهٔ واقعی چاپ می‌کند (حالت پورت، تعداد پروسه‌های Qoder، و زمانِ نوشتنِ `DevToolsActivePort` نسبت به همین اجرا) به‌جای یک حدس.

خروجی `--check` چهارده سطر PASS/FAIL می‌دهد: دیدن پنجره‌ها، پاسخ پروب‌ها، تزریق `window.__QODER_RTL__`، نصب استایل inline، **ثبت فونت وزیرمتن از بایت‌های inline**، قابل استفاده شدن فونت، رسیدن `font-family` به خودِ پاراگراف‌های چت، **برابر بودن `line-height` محاسبه‌شده با مقدار پنل**، **تأثیر واقعی دو اسلایدر فاصلهٔ خطوط و اندازهٔ متن**، **تأثیر اسلایدر اندازهٔ فونت کد روی جعبهٔ `<code>` درون‌خطی**، **راست‌چین شدنِ خودِ پیام‌های شما (حباب کاربر) نه فقط پاسخ‌ها**، دیدن قلاب‌های چت (`[data-chat-*]`)، فعال بودن پچ روی ریشهٔ سند و **نمایش پنل تنظیمات در پایینِ راست** (فاصله‌اش از لبه‌ها و اینکه روی هیچ دکمهٔ fixed خودِ Qoder نیفتاده باشد). سطری که پروبش جواب ندهد `UNSURE` است نه FAIL؛ سطرِ کد هم وقتی در آن گفت‌وگو هیچ `<code>` درون‌خطی رندر نشده `UNSURE` می‌گوید (با نامِ «no inline code rendered to measure») چون ویژگی‌ای که هیچ‌جا سنجیده نشده نباید «کار می‌کند» گزارش شود. سطرِ حباب کاربر هم از همان قاعده است: اگر آن گفت‌وگو هیچ پیامِ خودِ شما را رندر نکرده باشد `UNSURE` می‌ماند («no user message rendered to measure»). سطر پنل فقط روی پنجره‌ای داوری می‌شود که واقعاً چت دارد، تا یک پنجرهٔ خالیِ همزمان نتواند سبزش کند — و اگر خودِ شما دکمه را با **Alt+Shift+R** پنهان کرده باشید (همهٔ پنجره‌ها `config.panel=false`)، همان سطر به‌جای FAIL عبارت «settings panel hidden on purpose» را نشان می‌دهد، چون پروب علاوه بر تعداد گره‌های `.qrt-widget` مقدار `panel` را هم از runtime می‌خواند. برای هر سطر FAIL یک راهنمایی هم چاپ می‌شود.

سطر «تأثیر واقعی اسلایدرها» یک سنجش **کارکردی** است: پروب از بیرون، `lineHeight` و `chatSize` را موقتاً روی `2.15` و `6` می‌برد، ارتفاع خط و `zoom` محاسبه‌شدهٔ همان پاراگراف را دوباره می‌خواند، و بعد مقدارهای خودِ شما را برمی‌گرداند (همان `apply()` که پنل صدا می‌زند؛ نتیجه در خروجی با کلید `settled` است و اگر برنگشت، سطر عبارت `config NOT restored` را نشان می‌دهد). یعنی اگر اسلایدری فقط ظاهرش تغییر کند و به متن نرسد، این سطر قرمز می‌شود. **اسلایدر سوم (`codeSize`) در یک گامِ جدا رانندگی می‌شود**، و این عمدی است: `chatSize` با `zoom` کل زیردرخت را بزرگ می‌کند — از جمله خودِ `<code>` — پس اگر هر دو با هم تست می‌شدند، جعبهٔ کد روی payloadِ **خاموش** هم بزرگ می‌شد و سطر سبز می‌گرفت (هر دو روی fixture دقیقاً `77.97 → 107.22` دادند). در گامِ کد، `lineHeight` و `chatSize` روی مقدارِ خودِ کاربرند و چک می‌کند که `same()` نمانده باشد: پروب فقط وقتی پاس می‌شود که جعبهٔ کد بزرگ شده باشد **بدون** این‌که هیچ عددِ دیگری از پاراگراف تکان بخورد.

**چرا اسلایدرها اول کار نمی‌کردند؟** Qoder روی خودِ عنصرِ متن کلاس‌های utility می‌گذارد — نمونهٔ واقعی از `--diagnose`: `p.my-0.text-sm.leading-6.text-text` — و `font-family` را هم روی `.markdown-body` ست می‌کند. قانون فقط روی کانتینر ⇒ هیچ‌وقت به `<p>` نمی‌رسید. پس در `rtl.css` سه چیز روی خودِ عناصر متن تکرار شده‌اند: `font-family: var(--qrt-stack) !important` (نه `inherit`، چون inherit مقدار `.markdown-body` را می‌گرفت)، `line-height: var(--qrt-leading) !important` برای بدنهٔ متن، و برای اندازهٔ متن به‌جای دست‌زدن به `font-size` هر عنصر، `zoom: var(--qrt-zoom)` روی کانتینر (`1 + chatSize/16`) — این‌طور اندازه‌های نسبی (تیترها، ریزنوشته‌ها) حفظ می‌شوند و با `text-sm` می‌جنگند. تیترها از قانون `line-height` مستثنا هستند تا سلسله‌مراتبشان نشکند.

**دو نقص دیگر که فقط روی Qoder واقعی دیده می‌شدند.** اول: `--check` در اجرای اول همان stylesheet قدیمی (۱٫۱٫۰) را نشان می‌داد — پریامبل CSS وقتی `<style data-qoder-rtl>` را می‌دید از ساختن دوباره صرف‌نظر می‌کرد، پس اجرای مجدد injector روی سندِ باز، کد JS را بالا می‌آورد ولی CSS را نه. حالا اگر برگه موجود باشد `textContent` همان گره بازنویسی می‌شود (تست مرورگر این مسیر را با اجرای دومِ `--check` می‌سنجد: باید دقیقاً یک `<style>` بماند و همهٔ سطرها سبز). دوم: خود Qoder برای تنظیم «اندازهٔ متن چت» قانونی با `!important` و انتخابگرِ چهارطبقه دارد — `html[data-font-size="small"] … .markdown-body p { line-height:24px !important }` — که با هر stylesheet تزریق‌شده‌ای می‌برد. راه‌حلِ منطقی رقابتِ specificity نبود: runtime مقدار `line-height … !important` را روی خودِ عناصر متن می‌زند (inline برندهٔ author !important است، هر چند specificity چقدر باشد) و صفت `data-qrt-lead` نگهبان بی‌اثر شدن دوباره است؛ با `off` شدن RTL یا `dispose()` همهٔ مهرها پاک می‌شوند. این قانونِ Qoder در fixture هم کپی شده تا اگر مهر زدن حذف شد، تست هدلس قرمز شود.

**جای دکمهٔ پنل:** گوشهٔ پایین-راهمِ پنجره از قبل اشغال بود — Qoder یک دکمهٔ کمک دایره‌ای ۲۸پیکسلی با `bottom-4.5 right-4.5` (۱۸px از هر لبه) دارد. چون z-index ما حداکثری است، تریگر روی آن می‌افتاد و کلیکِ دکمهٔ کمک را می‌بلید؛ حالا `right:52px` است. پروب به‌جای اعتماد به این عدد، مستقیماً تقاطع مستطیل تریگر را با هر عنصر fixed دیگرِ صفحه می‌شمارد (`cornerClash`) و اگر غیرصفر باشد همان سطر FAIL می‌شود — fixture هم یک دکمهٔ کمکِ ساختگی با همان هندسه دارد، پس برگرداندن آفست به ۱۴px در تست خودکار گرفته می‌شود.

**چرا در روش CDP فونت با `FontFace` ثبت می‌شود نه با `url(data:)`؟** هیچ فایلی روی دیسک گذاشته نمی‌شود، پس بایت‌های وزیرمتن (~۱۱۱KB) داخل خود payload می‌آیند. اگر آن را به‌صورت `@font-face{src:url(data:…)}` بگذاریم، یک `font-src` سخت‌گیرانه (بدون `data:`) آن را رد می‌کند — این را روی Chromium تست کردیم: با `font-src 'self'` نتیجه `NetworkError` و `status=error` شد. صورتِ ثبت‌شده با `new FontFace(family, Uint8Array)` و `document.fonts.add()` هیچ fetchی انجام نمی‌دهد، پس `font-src` اصلاً دخالت نمی‌کند؛ همان تست در همان صفحه با همان CSP سبز شد. کد `@font-face{src:url(data:…)}` فقط به‌عنوان fallback برای موتور بدون `FontFace` در زمان اجرا ساخته می‌شود. اسکریپت تزریق‌شده از CSP معاف است، ولی داخلش `eval`/`new Function` نیست تا با `script-src 'self'` هم سازگار بماند.

### نکتهٔ امنیتی

`--remote-debugging-port` یک endpoint محلی باز می‌کند که هر پروسهٔ در حال اجرای همان کاربر می‌تواند آن را کنترل کند. پورت فقط روی `127.0.0.1` است و با بستن Qoder بسته می‌شود، اما روی سیستم مشترک/سازمانی این را روشن نگذارید و در انتهای کار پرچم را بردارید (اجرای معمولی Qoder از شورتکات خود برنامه).

```bash
qoder-rtl status                 # نسخهٔ ابزار/payload/Qoder، باز بودن پورت دیباگ، بودن launcher، و در دسترس بودن مسیر آرشیو
qoder-rtl patch --yes            # اعمال پچ (UAC می‌خواهد) — روی Qoder 0.3.3 اجرا نکنید، توضیحش پایین است
qoder-rtl restore                # بازگردانی آخرین archive اصلی
```

اگر پکیج را نصب نکرده‌اید، موتورهای مستقیم همان کار را می‌کنند: `node index.js --verify` (آرشیو پچ‌شده را در Temp می‌سازد و اعتبارسنجی می‌کند؛ نصب دست‌نخورده) و `node index.js --status`.

روی Qoder 0.3.3 ویندوز این روش باعث می‌شود **Qoder اصلاً باز نشود** و باید `--restore` بزنید. دلیل (با شواهد تأیید شده):

- fuse مربوطه در `Qoder.exe` روشن است: `EnableEmbeddedAsarIntegrityValidation = 1`
- یک منبع PE با نوع `#1033` و نام `ELECTRONASAR` مقدار SHA256 هدرِ `app.asar` را پین کرده است؛ هر تغییر در هدر ⇒ الکترون در bootstrap رد می‌کند (بدون لاگ، بدون Event Log).
- هر ۴۴۹۸ عضو آرشیو هم `integrity`per-file دارند، پس جابه‌جایی بایت‌ها هم قابل تشخیص است.

نتیجه: تا وقتی امضا/هش پین‌شده در `Qoder.exe` دست نخورده باشد (که در این پروژه **انجام نمی‌شود**؛ امضای Authenticode را می‌شکند)، روش CDP تنها راه سالم است. کد asar برای نصب‌هایی که این fuse را ندارند نگه داشته شده و همچنان تست می‌شود.

## چه کاری انجام می‌دهد (هر دو روش)

- **فقط محتوای چت و کادر ورودی** راست‌چین می‌شود؛ نوار کناری، تب‌ها و پنل‌ها LTR می‌مانند (`<html dir="ltr">` قفل است).
- **جداسازی دوجهته:** `unicode-bidi: plaintext` برای متن؛ `pre/code`، Monaco/CodeMirror، ترمینال و مسیر فایل‌ها همیشه LTR و ایزوله.
- **تشخیص هوشمند:** شمارش نویسهٔ فارسی-عربی در برابر لاتین برای هر پاراگراف/لیست/تیتر، و **مهر‌کردن هر دو حالت** (`.qrt-fa` یا `.qrt-en`) — قبلاً فقط کلاس فارسی اضافه می‌شد، پس بلوکی که هرگز فارسی نشده بود بی‌کلاس می‌ماند و زیرِ قانونِ پایه به‌صورت انگلیسیِ راست‌تراز درمی‌آمد (روی چت واقعی: ۶ بلوک از ۱۸). شمارش فقط از **نثرِ خودِ بلوک** است: محتوای `<code>`/`<kbd>` حذف می‌شود (استایل‌شیت آن را LTR قفل می‌کند، پس نمی‌تواند جهتِ جمله را تعیین کند — نام‌بردن از چهار شناسه، جملهٔ فارسی را چپ‌تراز می‌کرد) و نویسه‌های بی‌عرض/کنترلِ دوجهته پیش از شمارش پاک می‌شوند، چون U+FEFF داخلِ بازهٔ فارسی است و چهار BOMِ ناشی از کپی‌پیچِ markdown یک خطِ انگلیسی را راست‌چین می‌کرد. لیست فقط وقتی می‌چرخد که **همهٔ** آیتم‌هایش لاتین باشند؛ لیستِ قاطی نشانگرهای RTL نگه می‌دارد و هر آیتم جهت خودش را دارد (حالت `force` همه را راست‌چین می‌کند).
- **فونت وزیرمتن متغیر و آفلاین**؛ هیچ درخواست شبکه‌ای انجام نمی‌شود و CSP دست‌نخورده می‌ماند.
- **حالت ریشه روی `data-qrt-*`:** استایل‌های اپ روی `<html class="…">` می‌نویسند و احتمال بازنویسی آن توسط رندرر هست، پس برای اینکه پچ هرگز بی‌صدا خاموش نشود CSS کلیدِ انتخابگرهایش را با صفت‌های `data-qrt-mode|tables|reverse` می‌خواند (کلاس‌های `qrt-*` فقط برای دیباگ آینه می‌شوند) و payload در هر تغییر DOM و هر ۴ ثانیه drift را بررسی و درست می‌کند. صفحهٔ تست این سناریو را فرض می‌کند: هر ۵۰۰ms کلاس‌های `<html>` را پاک می‌کند و انتظار دارد پچ سبز بماند.
- **خودترمیمی گره‌های `<style>` (۱٫۶٫۰):** صفت‌های ریشه تنها جای ممکنِ خرابی نیستند. اگر گرهٔ `<style>` تزریق‌شده از DOM برود — رندرر دوباره `<head>` را بسازد، افزونه‌ای دست بزند، هر چیزی — متغیرهای CSS با آن می‌افتند: فونت به `system-ui` برمی‌گردد، `zoom` روی ۱ می‌نشیند و فاصلهٔ خطوط می‌رود، در حالی که **هر سه صفت ریشه هنوز درست خوانده می‌شوند**. آن خرابی بی‌صدا و همیشگی بود، چون `applyConfig()` فقط وقتی driftِ ریشه دیده می‌شد اجرا می‌گردید. حالا همان observer و همان تیکت ۴ ثانیه‌ای وجودِ `#qoder-rtl-vars`، `#qoder-rtl-panel-style` و `<style data-qoder-rtl>` را هم می‌بینند و در صورت نبود باز می‌سازند (برگهٔ اصلی از طریق `window.__QRT_CSS__` که پریامبل خودش را export می‌کند بازمی‌گردد، پس متن CSS در payload دو نسخه نمی‌شود). در تست مرورگر هر سه گره واقعاً حذف می‌شوند و ۴۰۰ms بعد دوباره باید آن‌ها را ببینید.
- **placeholder کادر ورودی (۱٫۶٫۰):** Qoder متنِ راهنمای کادر ورودی را روی یک لایهٔ `aria-hidden` جدا می‌گذارد — در پنجرهٔ واقعی اندازه گرفته شد: `position:absolute; inset:0` با فونت خودِ اپ (`-apple-system…`)، `line-height:24px` و جعبهٔ `ltr` — پس placeholder از همان پاراگرافی که مکان‌نما روی آن است، فونت و جهتِ دیگری داشت. حالا همان قانون‌هایی که ادیتور را می‌گیرند `placeholder` را هم در هر چهار حالت (پایه/`force`/`off` و فهرست `line-height` و `font-family`) با خود می‌برند.
- **کلید «RTL جدول‌ها» حالا کل جدول را مالک است (۱٫۷٫۰):** قانونِ پایهٔ جهت، `direction: rtl` را روی `td/th/caption` هم می‌نشاند، در حالی که صفتِ `data-qrt-tables` فقط روی `table` اثر داشت — پس خاموش‌کردنِ آن کلید ستون‌ها را به چپ برمی‌گرداند ولی **متنِ سلول‌ها راست‌تراز می‌ماند**: یک سوییچِ نیمه. اندازه‌گیری روی کدِ قبلی (Edge هدلس، همان fixture): `{on: rtl/right, off: rtl/right, offColumns: left}`. حالا هر دو نیمه زیرِ `html[data-qrt-tables]` اند، پس با خاموش‌کردنِ کلید جدول دقیقاً برمی‌گردد به حالتِ خودِ اپ.
- **`figcaption` و `summary` هم جهتِ خودشان را می‌گیرند (۱٫۷٫۰):** همان نقصِ ۱٫۴٫۰ (بلوکِ بی‌کلاس زیرِ قانونِ پایه راست‌تراز می‌ماند) روی این دو تگ باز بود: قانونِ پایه هر دو را RTL می‌کرد ولی شمارش‌گرِ هوشمند هرگز سراغشان نمی‌رفت، پس `Figure 1: allowed speed` راست‌تراز می‌شد. الآن در `BLOCK_SELECTOR` و در هر دو فهرستِ `.qrt-fa/.qrt-en` هستن. `caption` و سلول‌ها **عمداً** خارج‌اند: آن‌ها را سوییچِ جدول اداره می‌کند، نه تشخیصِ زبان.
- **مهرِ فاصلهٔ خطوط و قانونِ CSS یک فهرست دارند (۱٫۷٫۰):** CSS روی `figcaption/caption/summary` هم `line-height: var(--qrt-leading) !important` می‌گذارد ولی `LEAD_SELECTOR`ِ رانتایم آن‌ها را نداشت — و همان مهرِ inline است که قانونِ `!important` خودِ Qoder را می‌برد، پس همان سه تگ روی ۲۴px می‌ماندند در حالی که بقیهٔ پیام اسلایدر را دنبال می‌کرد (همان ظاهرِ «اسلایدر نصفه کار می‌کند»). یک چکِ سورس حالا دو فهرست را با هم مقایسه می‌کند، نه فقط مقدارشان را؛ ضمناً `[data-chat-composer][contenteditable]` حذف شد چون روی DOMِ واقعی هیچ گره‌ای را نمی‌گرفت (کانتینرِ کامپوزر ادیتور نیست).
- **پنجره‌ای که جواب نمی‌دهد از گزارشِ `--check` غیب نمی‌شود (۱٫۷٫۰):** قبلاً اگر `Page.enable` وقت تمام می‌شد، session از `sessions` حذف می‌شد و آن پنجره **حتی در سطرِ «page targets visible over CDP» هم شمرده نمی‌شد** — یعنی اجرای ۱ از ۲ پنجره ظاهری شبیه اجرای ۱ پنجره داشت. حالا در `skipped` می‌ماند، سطرِ خودش را با عبارت `NOT PATCHED` و دلیلش می‌گیرد، در شمارشِ targetها هست، و یک hint می‌گوید که تا وقتی injector باز است هر ۱۵ ثانیه دوباره امتحان می‌شود (`retrySkipped`).
- **متن‌های خودِ ابزار تصحیح شد (۱٫۷٫۰):** کنسولِ `live.js` و خروجیِ `index.js` هنوز «دکمهٔ «ا» در گوشهٔ بالا-راست» را تبلیغ می‌کردند؛ دکمه دو batch است که SVG است و پایینِ راست. یک چکِ سورس حالا هیچ «ا» یا `top-right` را در این دو فایل راه نمی‌دهد.
- **اسلایدر «اندازهٔ فونت کد» روی Qoder واقعی کار می‌کند (۱٫۸٫۰):** تا پیش از این آن اسلایدر `font-size: calc(1em * var(--qrt-code-scale))` اعلام می‌کرد. روی پنجرهٔ زنده اندازه گرفته شد: `<code>` درون‌خطی داخل یک `<p>` سیزده‌پیکسلی، `12px` محاسبه می‌شود — و همان‌جا `font-family: … !important`ِ **همان بلوکِ قانون** به گره می‌رسید ولی `font-size`ِ بدون `!important` هرگز. یعنی یک نیمهٔ اعلامی زنده بود و نیمهٔ دیگرش خاموش، و اسلایدر هیچ‌چیز را تکان نمی‌داد. حالا اندازه را اعلام نمی‌کند بلکه **مقیاس** می‌دهد: `zoom: var(--qrt-code-scale)` روی خودِ جزیرهٔ کد، پس هر عددی که اپ انتخاب کرده ضرب می‌شود و در حالت صفر دقیقاً همان اندازهٔ خودِ اپ می‌ماند. `<pre>` هم مقیاس می‌گیرد، ولی `.monaco-editor`/`.cm-editor`/`.xterm` عمداً بیرون‌اند: آن‌ها خودشان برای چیدمانشان پیکسل اندازه می‌گیرند و `zoom` دوم را بد می‌گیرند. روی Qoder واقعی: کد `57.22px → 78.69px` در همان `font-size: 12px` (مقیاس ۱٫۳۷۵).
- **خودترمیمی دیگر ترتیبِ برگه‌ها را به تنظیمات شما نمی‌خورد (۱٫۸٫۰):** `#qoder-rtl-vars` و `rtl.css` هر دو یک مجموعه خاصیت سفارشی روی `:root` اعلام می‌کنند، پس **کدام‌شان دیرتر در `<head>` باشد برنده است**. آن ترتیب پایدار نیست: اگر اپ فقط `<style data-qoder-rtl>` را حذف کند، مسیر ترمیم همان گره را دوباره به **انتهای** `<head>` بازمی‌گرداند — یعنی پشتِ برگهٔ متغیرها — و مقدارهای پیش‌فرضِ CSS جای عدد شما را می‌گیرند: `zoom` به ۱ برمی‌گردد و فونتی که تایپ کرده‌اید ناپدید می‌شود، بی‌صدا و برای کل همان جلسه. روی fixture اندازه گرفته شد: پس از یک ترمیم `{zoom:"1", face:"Vazirmatn QRT, Segoe "}`. حالا **هر** اعلامِ آن برگه `!important` دارد تا برنده بودنش به ترتیبِ گره‌ها وابسته نباشد.
- **خودِ پیام‌های شما هم راست‌چین می‌شوند (۱٫۸٫۱):** حبابِ پیام کاربر همان `data-chat-message-text` را دارد، ولی Qoder متن را **روی خودِ کانتینر** می‌گذارد — بدون `<p>` و بدون `.markdown-body` — پس هر قانونی که از `[data-chat-message-text]` پایین می‌رفت آن را رد می‌کرد و فقط پاسخ‌ها راست‌چین می‌شد. `[data-user-bubble] [data-chat-message-text]` حالا در هر شش گروهِ قانون هست (ترازِ پایه، جهتِ پایه، `.qrt-fa`/`.qrt-en` در حالت smart، force و off) و همان صفت هم به `BLOCK_SELECTOR` (تا زبانِ خودش تشخیص داده شود) و به `LEAD_SELECTOR` (تا مهرِ فاصلهٔ خطوط) اضافه شد؛ افزودنِ نصفه‌اش همان نقصِ ۱٫۴٫۰ را برمی‌گرداند — یعنی یک بلوکِ راست‌ترازِ اجباری که هیچ‌کس دربارهٔ زبانش نظر نداده.
- **برعکس‌کردن ستون‌های جدول (۱٫۶٫۰):** ترتیب ستون‌ها را `direction` روی **خودِ `<table>`** تعیین می‌کند. قانون قبلی روی جدولِ از پیش `rtl` دوباره `direction: rtl` می‌ذاشت و `display: table` را تکرار می‌کرد — یعنی آن کلید **هیچ ستونی را جابه‌جا نمی‌کرد** (در تست اندازه گرفته شد: سرستونِ اول با روشن‌کردنِ گزینه باز هم سمتِ راست ماند). سطرِ تازه جدول را به `ltr` برمی‌گرداند تا ستون‌ها در ترتیبِ منبع بنشینند. توضیحِ قبلیِ خودم هم غلط بود و تصحیح شد: آن قانون سلول‌ها را هم `ltr` می‌کرد و من نوشته بودم این «bidi داخل سلولِ فارسی را به هم می‌ریزد» — اندازه‌گیری نشان داد **هیچ به‌هم‌ریختگی‌ای رخ نمی‌داد**، چون این سلول‌ها `unicode-bidi: plaintext` دارند و جهتِ پایهٔ متن را محتوایش تعیین می‌کند نه آن صفت. پس آن بخشِ قانون عملاً بی‌اثر بود و حذف شد؛ فقط جابه‌جاییِ جدول مانده است.
- **پنل شناور پایینِ راست:** دکمهٔ ۳۴پیکسلی با آیکون SVG (چند خطِ راست‌تراز به‌همراه یک فلش چپ‌گرا؛ همان معنای «متن راست‌به‌چپ»، بدون حرفِ «ا» که روی دکمهٔ کوچک شبیه تایپو می‌شد) در گوشهٔ پایین-راهمِ پنجره، `52px` از لبهٔ راست تا روی دکمهٔ کمکِ خودِ Qoder نیفتد، و پنل به سمت بالا باز می‌شود تا روی پاسخِ در حال خواندن نیفتد. **فقط با کلیک باز می‌شود** — هاورِ گوشه قبلاً پنل را خودش باز می‌کرد؛ با کلیک بیرون از پنل بسته می‌شود، **Escape** هم همان کار را می‌کند و فوکوس را به خود دکمه برمی‌گرداند، و وقتی بسته است `inert` است (اسلایدرهایش در tab order نمی‌مانند). «پنهان کردن پنل» هم اول آن را می‌بندد تا بعد از **Alt+Shift+R** بازِ از قبل برگردد. کلید **Alt+R** (جهت) و **Alt+Shift+R** (نمایش/پنهان‌کردن خود دکمه؛ حالت پنهان فقط در localStorage است و بدون این کلید راه بازگشت ندارد). **کلِ تصمیمِ جهت از یک تابع واحد می‌گذرد** (`setDirection`): `rtl:false` و `mode:"off"` دو نامِ یک حالت‌اند، پس سوییچ master همیشه *وضعیتِ واقعیِ صفحه* را نشان می‌دهد نه فلگِ ذخیره‌شده را. قبلاً این یکی نبود: خاموش/روشن‌کردنِ سوییچ، `mode` را روی `off` رها می‌کرد، یعنی سوییچ ON بالای صفحه‌ای نشسته بود که هنوز چپ‌تراز بود (و همین‌طور انتخاب «خاموش» از dropdown، سوییچ را ON نگه می‌داشت)؛ به‌همین دلیل **Alt+R** هم دو بار فشار می‌خواست تا اثر کند، و حالا یک بار کافی است. اگر خودِ Qoder گرهٔ پنل را وسط کار از DOM بردارد، payload روی همان MutationObserver آن را دوباره می‌سازد و منتظر تیکت ۴ ثانیه‌ای نمی‌ماند. تنظیمات بین پنجره‌ها همگام می‌ماند (`storage`)، و «بازگردانی همه» آبجکت config را در جا تغییر می‌دهد نه اینکه جایگزینش کند — وگرنه `window.__QODER_RTL__.config` تا همیشه عددهای قبل از ریست را گزارش می‌کرد. گزینه‌ها: اندازهٔ متن چت (با `zoom`، پس تیترها نسبی می‌مانند)، اندازهٔ فونت کد، فاصلهٔ خطوط (که برخلاف قبلی هیچ‌وقت با خاموش‌کردنِ جهت از کار نمی‌افتد)، راست‌چین کردن جدول‌ها و برعکس‌کردن ستون‌ها، فونت فارسی/لاتین/کد، و اصلاح کلید `@` روی کیبورد فارسی.
- تنظیمات در `localStorage` کلید `qoder_persian_rtl_config_v1` ذخیره می‌شود (در روش CDP داخل همان profile می‌ماند).

**مرحلهٔ چهارم (`geometryTest`) چیزی را که فقط با «خواندنِ CSS» قابل سنجش نیست اندازه می‌گیرد:** موقعیتِ x دو سرستون پیش و پس از روشن‌کردنِ «برعکس‌کردن ستون‌ها» (باید عوض شود — روی کدِ قبلی ثابت ماند و سطر قرمز شد)، جهت و ترازِ یک `<td>` فارسی در همان حالت، و فونت/جهت/نسبتِ خطِ **placeholder** کادر ورودی در مقایسه با ادیتورِ زیرش (قبلاً `-apple-system` روی `24px` و `ltr` بود). fixture برای همین به شکلِ واقعیِ اندازه‌گرفته‌شده روی Qoder بازسازی شد: کانتینر `[data-chat-composer]` → `div.loop-rich-editor[contenteditable]` + لایهٔ خواهر `[data-chat-composer-placeholder]`. بعد همان سه گرهٔ `<style>` تزریق‌شده واقعاً از DOM حذف می‌شوند و ۴۰۰ms بعد تست انتظار دارد هر سه برگشته باشند و `font-family` محاسبه‌شده دوباره Vazirmatn باشد (روی کدِ قبلی: `system-ui` و صفر گره).

**هر ادعای تازه هم روی payload قبلی سرخ می‌شود.** تست‌های این batch داخل یک `git worktree` دورریز روی نسخهٔ قدیمی اجرا شدند تا معلوم شود واقعاً چیزی را می‌گیرند: ۲۱ از ۲۱ چکِ سورس و هر شش چکِ رفتاری (مثلاً سوییچِ خاموش→روشن با خروجیِ `{root:"off", rtl:true, checked:true, dir:"ltr"}`) روی کدِ معیوب قرمز شدند. یک چک که روی کدِ خراب‌شده سبز بماند، چک نیست. در batch سوم این قاعده **دو بار** کار کرد: هفت چکِ سورسِ تازه و چهار چکِ اندازه‌گیری‌شده همه روی payload ۱٫۳٫۰ سرخ شدند ( `{plain:"right", reversed:"right"}` برای ترتیب ستون، `dir:"ltr"` برای سلول، `ghost:-apple-system/24/ltr` و `{vars:false, sheetNodes:0, face:"system-ui"}` برای خودترمیمی) — و یک چک که نوشته بودم «bidi داخل سلول را می‌سنجد» روی کدِ خراب **سبز** ماند؛ همان‌جا فهمیدم `unicode-bidi: plaintext` جهتِ پایه را از محتوا می‌گیرد نه از صفتِ `direction`، پس آن ادعا غلط بوده: چک حذف شد و توضیحِ CSS هم تصحیح شد. عددِ کل چک‌ها: `npm test` = ۹۱ ok، `npm run test:browser` = ۴۶ ok.

**یک نقصِ خودِ ابزارِ تست، نه payload (همین روز پیدا شد).** اجرای مرورگر یک Edge هدلسِ موقت با پورت ۹۳۳۳ می‌سازد؛ اگر آن پورت بالا نیاید، پروسه‌ای که *خودِ تست* spawn کرده زنده می‌ماند و پورت را نگه می‌دارد — و از آن به بعد هر اجرای جدید با پیامِ گمراه‌کنندهٔ «nothing listened on 9333» می‌سوزد، یعنی دقیقاً برعکسِ علتِ واقعی (یک مرورگرِ اشغال‌کننده، نه پورتِ بی‌جواب). دو تغییر داده شد: مسیرِ شکستِ `startBrowser` حالا همان بچهٔ spawn‌شده را می‌کشد، و قبل از بالا آوردن، اگر پورت از قبل DevTools می‌داد، تست با «port is free before launch» می‌سوزد و **آن پروسه را نمی‌کشد** — چون مالِ این اسکریپت نیست. خودِ همین سناریو هم روی نسخهٔ قبلی سرخ شد (۲/۲).

**چه چیزی کجا تأیید شده:** روی Qoder واقعی با payload ۱٫۱٫۰ (۲۰۲۶-۰۹-۲۰): پورت دیباگ باز شد، پچ به هر دو پنجره رسید، متن راست‌چین شد، **فونت وزیرمتن اعمال شد و پنل باز شد**، و ۹/۱۰ سطر سبز بودند؛ سطر قرمز همان اجرا «chat prose computes to the Vazirmatn stack (system-ui)» بود — یعنی فونت ثبت شده بود ولی به خودِ `<p>` نمی‌رسید، و به همان دلیل دو اسلایدر فاصلهٔ خطوط و اندازهٔ متن بی‌اثر بودند.

**بازتأیید همان روز با payload ۱٫۳٫۰ روی Qoder واقعی: ۱۲/۱۲ سطر سبز** — `prose → "Vazirmatn QRT"`، `lineHeight 24.05px = 1.85` روی متن ۱۳پیکسلی (مقدار پنل)، پروب اسلایدرها `24.05→27.95px` و `zoom 1→1.375` و برگشت به مقدار کاربر، و پنل `14px` از پایین / `52px` از راست با `cornerClash n=0` (دکمهٔ کمکِ خودِ برنامه دیگر زیرش نیست). همان‌جا دو نقصِ دیگر هم رفع شد: بازنویسی inline stylesheet هنگام تزریق دوباره (قبلاً CSS قدیمی روی سندِ باز می‌ماند) و مهرِ inline روی `line-height` برای بردن قانون `!important` خودِ Qoder. همان‌جا رفتارِ دکمه هم با رویدادِ ماوس واقعی روی همان پنجرهٔ زنده سنجیده شد: هاور روی دکمه ⇒ پنل باز **نمی‌شود** (`open:false`)، کلیک ⇒ باز شدن (`aria-expanded=true`، پنل از `inert` خارج)، کلیکِ بیرون ⇒ بسته شدن.

**بازتأیید روز بعد (۲۰۲۶-۰۹-۲۱) با payload ۱٫۴٫۰ روی همان Qoder واقعی: دوباره ۱۲/۱۲ سطر سبز** (stylesheet تک‌گره، `bytes=6689`)، و مهم‌تر از عددِ سبزها، خودِ تشخیص هوشمند روی چت واقعی اندازه گرفته شد: ۱۸ بلوکِ متن ⇒ `۱۲ .qrt-fa` + `۶ .qrt-en`، و شش بلوک لاتین `direction: ltr; text-align: left` می‌گیرند در حالی که **قبل از این اصلاح هیچ کلاسی نداشتند و زیرِ قانونِ پایه راست‌تراز نشسته بودند**؛ تک `<ul>` زنده هم `{dir: rtl, fa: 3, en: 0}` ماند (لیستِ قاطی نمی‌چرخد). همان‌جا دو رفتار هم از بیرون سنجیده شد: نوشتنِ config در `localStorage` و صدازدنِ `reset()` — بعد از ریست `window.__QODER_RTL__.config` هنوز ۲٫۰۵ را گزارش می‌کرد در حالی که ذخیره‌شده ۱٫۷۵ بود، که همان آبجکتِ بیاتِ ریست‌شدن است. چیزی که آن روز روی Qoder واقعی هنوز تأیید نشده بود: عمرِ پچ بعد از self-restart دیده‌شده (≈۸ ثانیه بعد از اتصال، پورت می‌میرد) و پنجرهٔ دومِ خالی که پروبش همیشه timeout می‌دهد (تصحیحش در پاراگراف ۱٫۶٫۰ و بخش «نصب و آپدیت» است).

**همان روز، payload ۱٫۵٫۰ روی همان پنجرهٔ زنده: دوباره ۱۲/۱۲ سطر سبز.** اندازه‌گیریِ تازهٔ تشخیص روی چت واقعی: ۱۹ بلوکِ متن ⇒ `۱۲ .qrt-fa` + `۷ .qrt-en`، که ۶ تای آن‌ها `<code>` درون‌خطی دارند. برای این‌که معلوم شود حذفِ محتوای کد از شمارش روی Qoder واقعی چه می‌کند، تشخیصِ قبلی و جدید روی **همهٔ** بلوک‌های زنده از بیرون دوباره محاسبه شد (فقط‌خواندنی، بدون تزریق): **هیچ بلوکی جهتِ خودش را عوض نمی‌کند**، پس این اصلاح به‌صورت *پیش‌گیرانه* ثبت می‌شود — سازوکارش را fixture ثابت می‌کند، نه چت واقعیِ امروز. همان پروب هر ۱۹ کلاسِ زنده را دقیقاً بازتولید کرد، و این هم ارزش نوشتن دارد: نسخهٔ اولِ همان پروب با regexهای literal **هیچ نویسه‌ای** پیدا نمی‌کرد و همهٔ پاراگراف‌های فارسی را لاتین گزارش می‌داد؛ نتیجه‌اش هم ظاهرش «بدون تفاوت» و تمیز درمی‌آمد. یک پروب که همه‌چیز را یک‌سان می‌بیند، همان‌قدر خطرناک است که پروبی وجود ندارد.

**payload ۱٫۶٫۰ روی همان نصبِ واقعی: دوباره ۱۲/۱۲ سطر سبز.** دو چیزِ تازه در همین اجرا دیده شد. اول این‌که خودِ عملیاتِ ممیزی از ۲۴٫۴ ثانیه به ۴٫۴ ثانیه افتاد، چون پنجرهٔ دوم دیگر پروب نمی‌شود: تا پیش از این، `report()` یک `Runtime.evaluate` روی sessionی می‌فرستاد که `onAttach`ِ آن هنوز وسط `Page.enable` بود، ده ثانیه timeout می‌گرفت، و بعد پروبِ کنترل‌ها ده ثانیهٔ دیگر — یعنی چیزی که در خروجی شبیه «پچ در آن پنجره شکست خورد» خوانده می‌شد، در حالی که هیچ تزریقی برای سنجیدن موجود نبود. حالا همان session با `busy` علامت می‌خورد، سطرِ گزارشش عبارت «still being attached when this report ran — nothing was probed» را نشان می‌دهد و یک hint هم توضیح می‌دهد که چند ثانیه بعد دوباره اجرا شود. دوم این‌که سه موردِ batch سوم (خودترمیمی، placeholder، ترتیب ستون‌ها) روی Qoder واقعی **اندازه گرفته نشدند** — fixture و تستِ مرورگر سنجیدندشان؛ عددِ ۱۲/۱۲ فقط همان دوازده سطرِ همیشگی است.

## نصب و آپدیت Qoder



روش CDP چیزی در نصب نمی‌نویسد، پس **آپدیت خودکار Qoder پچ را پاک نمی‌کند** — فقط برای هر بار اجرای Qoder باید `npx qoder-persian-rtl` (یا `qoder-rtl start`) را دوباره اجرا کنید؛ اگر شورت‌کات دابل‌کلیکی را ساختید، همان `Qoder-RTL.cmd`. اگر خواستید حذفش کنید: `qoder-rtl remove-launcher` (یا پاک کردن همان `.cmd`)؛ هیچ اثری روی فایل‌های برنامه نیست.

**هر بار Qoder بدون `--remote-debugging-port` بالا بیاید، پچ از بین می‌رود.** این فقط دربارهٔ اجرای بعدی نیست: در تست ۲۰۲۶-۰۹-۲۰ حدود ۸ ثانیه بعد از اتصال، پورت ۹۲۲۲ دیگر گوش نمی‌داد و پروسه‌های جدید Qoder بدون آن پرچم در خط فرمان دیده شدند (هیچ فایل `DevToolsActivePort` هم ساخته نشده بود). این‌ها با هم نشانهٔ self-restart هستند. **اما قطعِ پورت دائمی نیست:** در جلسهٔ payload ۱٫۵٫۰ (۲۰۲۶-۰۹-۲۱) همان پورت بیش از ۴۵ دقیقه و در چهار اجرای جداگانهٔ injector به هر درخواست جواب داد و آن مرگِ ۸ ثانیه‌ای تکرار نشد. پس درست‌تر این است که بگوییم *متناوب و بی‌علتِ شناخته‌شده*، نه «پچ روی این نصب عمر کوتاه دارد»: نتیجهٔ عملی برای هر دو حالت یکی است — بعد از هر بالا آمدن Qoder باید `Qoder-RTL.cmd` (یا `node live.js`) را دوباره اجرا کرد، و اگر در میانهٔ کار پچ غیب شد، اولین حدس همان self-restart است. علت قطعی هنوز تأیید نشده است. **پنجرهٔ دومِ بی‌نقشه هم سرِ جایش مانده، فقط درست گزارش می‌شود:** آن target در `Target.getTargets` دیده می‌شود ولی `Page.enable` رویش در ۸ ثانیه جواب نمی‌دهد (سند نقاشی نشده)، پس injector آن session را رها می‌کند و لاگِ `skipped (no Page domain)` را می‌نویسد؛ یعنی **آن پنجره در همان اجرا هرگز پچ نمی‌شود** — چیزی که payload ۱٫۶٫۰ عوض کرد این است که دیگر به‌جای یک timeout بیست‌ثانیه‌ایِ گمراه‌کننده، سطرِ خودش را با عبارت «still being attached» و یک hint می‌خوانید. ۱٫۷٫۰ دو قدم جلوتر رفت: آن target حالا در شمارشِ گزارش **هست** و سطرش واژهٔ `NOT PATCHED` و دلیلش را نشان می‌دهد، و تا وقتی injector در حالت watch باز است هر ۱۵ ثانیه با `retrySkipped()` دوباره امتحان می‌شود؛ یعنی «۱ از ۲ پنجره» دیگر شبیه اجرای تک‌پنجره‌ای به‌نظر نمی‌رسد. راهِ پیشنهادی (اجرای دوباره، تا سندِ آن پنجره نقاشی شده باشد) **روی این نصب تأیید نشده**: تا امروز آن target در همهٔ اجراها بی‌نقشه مانده است. خودِ مسیرِ `retrySkipped()` هم **رفتاراً سنجیده نشده** — سه چکِ سورس ثابت می‌کنند که skip در `skipped` ثبت می‌شود، در `report()` سطری با `NOT PATCHED` می‌سازد، و تیکتِ watch آن را صدا می‌زند؛ این‌که یک target بی‌جوابِ واقعی در اجرای دوم جواب بدهد، روی این نصب هنوز دیده نشده است.

## طرز کار فنی روش CDP

1. اتصال به `http://127.0.0.1:<port>/json/version` و باز کردن WebSocketِ مرورگر.
2. `Target.setAutoAttach` + `Target.getTargets` ⇒ هر target صفحه‌ای (پنجرهٔ Qoder) یک session می‌گیرد.
3. برای هر session: `Page.addScriptToEvaluateOnNewDocument` (قبل از اسکریپت‌های خود صفحه و معاف از CSP) و یک `Runtime.evaluate` فوری برای سندِ باز شده.
4. source تزریقى سه تکه است: پریامبل فونت (ثبت `FontFace` از بایت‌های base64ِ همان فایل، با fallback به `@font-face{src:url(data:…)}` که در زمان اجرا ساخته می‌شود) + پریامبل استایل inline (rtl.css بدون قاعدهٔ `@font-face`) + بدنهٔ `patches/rtl.js` (همان فایل روش asar). بایت‌های فونت فقط یک بار در source می‌آیند.
5. پروب `--check` از همان صفحه: نسخه، وجود `<style data-qoder-rtl>`، وضعیت `window.__QRT_FONT__`، `document.fonts.check("Vazirmatn QRT")`، و روی نخستین بلوک `.qrt-fa`: `fontFamily`/`fontSize`/`lineHeight`/نسبت خط و `zoom` کانتینر؛ به‌علاوهٔ مستطیلِ خودِ `<code>` درون‌خطی (پهنا/بلندا/اندازهٔ محاسبه‌شده، که `null` است اگر چنین گره‌ای رندر نشده باشد)، صفت `data-qrt-mode` روی `<html>`، شمارش قلاب‌های چت و فاصلهٔ `.qrt-widget` از لبهٔ پایین و راست پنجره. یک پروب دوم (`controls`) موقتاً `lineHeight` و `chatSize` را عوض می‌کند تا تأثیر واقعی‌شان روی متن سنجیده شود، سپس در گامی جدا فقط `codeSize` را (تا `zoom`ِ اندازهٔ متن، بزرگ‌شدنِ کد را به خودش نسبت ندهد) و بعد همه را برمی‌گرداند.

# English

Two ways to add Persian/Arabic RTL, an **offline Vazirmatn** font and correct bidi handling to the Qoder desktop chat:

- **`live.js` (recommended)** — injects the patch into the running Electron renderer over the DevTools protocol. No install file is modified, nothing breaks on update, and Qoder 0.3.3 accepts it.
- **`index.js`** — rewrites `app.asar` (with backup and `--restore`). On this Qoder build the app then **refuses to start**, because `EnableEmbeddedAsarIntegrityValidation` is on and `Qoder.exe` carries an `ELECTRONASAR` resource pinning the SHA256 of the archive header. Kept only for builds without that fuse; the signed binary is never touched.

**Scope (both routes):** chat messages and composer only — app chrome stays LTR (`<html dir="ltr">` pinned). Code, editors, terminals and file paths stay LTR and bidi-isolated; direction is detected per block from **that block's own prose** — inline `<code>`/`<kbd>` contents are excluded, because the stylesheet already pins them LTR and naming four identifiers used to outvote the Persian sentence around them and left-align it — and zero-width/bidi-format characters are masked before counting, since U+FEFF sits inside the Persian range. **Both** verdicts are stamped (`.qrt-fa` *and* `.qrt-en`) — stamping only the Persian one left a Latin paragraph with no class at all, so it fell under the base RTL rule and showed right-aligned English; a list flips wholesale only when every item in it is Latin, and a mixed list keeps RTL markers with each item carrying its own direction. `Alt+R` toggles direction and `Alt+Shift+R` shows or hides the settings button — a 34px SVG icon (right-aligned lines with a left arrow, not a lone «ا» glyph, which read as a typo at 26px) that sits at the **bottom-right** of the window next to the composer and opens its panel upward. The switch and the حالت جهت dropdown are one decision with two names (`rtl` and `mode==="off"` both mean off), so every path — switch, dropdown, shortcut — goes through a single setter and the switch shows the *effective* state: before that, turning direction off and back on with the switch left `mode` at `off`, so the master toggle read ON over a page that stayed left-aligned, and Alt+R needed two presses. It opens on **click only**: hovering the corner used to pop it open by itself. Clicking anywhere outside closes it and **Escape** closes it too, handing focus back to the button; while closed the panel is `inert`, so its sliders leave the tab order, and hiding it (`پنهان کردن پنل`, or `Alt+Shift+R`) closes it first so it cannot come back already expanded. Settings are shared across Qoder's windows through a `storage` listener, so a slider moved in one window re-applies in the other, and `بازگردانی همه` mutates the config object in place — `window.__QODER_RTL__.config` used to keep pointing at the replaced one, so every probe afterwards reported the pre-reset numbers. The button is inset `52px` from the right edge because Qoder's own 28px help button occupies the last 46px of that corner and our maximal z-index would swallow its clicks. Root state is carried on `data-qrt-*` attributes rather than classes, because the app's own renderer owns `<html class>`; a widget the app detaches mid-stream is re-mounted by the mutation observer rather than waiting for the 4 s safety tick. That drift check does not stop at the root attributes (1.6.0): if the injected `<style>` nodes themselves leave the DOM — the renderer rebuilds `<head>`, an extension touches it — the CSS custom properties go with them, so the font drops back to `system-ui`, `zoom` returns to 1 and the leading is gone while **all three root attributes still read correctly**. That failure used to be silent and permanent, because `applyConfig()` only ran when root drift was seen; the same observer and the same 4 s tick now also look for `#qoder-rtl-vars`, `#qoder-rtl-panel-style` and `<style data-qoder-rtl>` and recreate what is missing (the main sheet comes back through `window.__QRT_CSS__`, which the CSS prelude exports, so the stylesheet text is not duplicated inside the payload). The composer's ghost text is covered by the same rules as the editor underneath it (1.6.0): Qoder puts it in a separate `aria-hidden` layer, measured live as `position:absolute; inset:0` with the app font, its own 24px leading and an `ltr` box — so the placeholder had a different typeface and direction from the line the caret was on. Reversing table columns (1.6.0) now really reverses them: column order follows the `direction` of the **`<table>` element**, and the old rule set `direction: rtl` on a table that was already rtl — measured, the first header stayed on the right with the toggle on, so the whole option was a no-op; the new rule puts the table back to `ltr`. My earlier explanation of that rule was wrong too and is retracted here: it also pinned cells to `ltr` and I claimed that "scrambled bidi inside Persian cells" — measurement showed **nothing was scrambled**, because those cells carry `unicode-bidi: plaintext`, which takes the base direction from the content rather than from that attribute. The redundant cell half of the rule is gone; only the table flip remains. **That table flip is now one switch's whole job (1.7.0):** the base direction rule also sat `direction: rtl` on `td`/`th`/`caption` unconditionally while `data-qrt-tables` only affected `<table>`, so switching the table option off moved the columns back to LTR and **left the text inside the cells right-aligned** — measured on the previous payload: `{on: rtl/right, off: rtl/right, offColumns: left}`. Both halves now live under `html[data-qrt-tables]`, so the toggle returns the table exactly to the app's own state. `figcaption` and `summary` got their own direction verdict (1.7.0): the 1.4.0 bug class — an unclassified block falling under the base RTL rule — was still open for those two tags, since the base rule RTL-pinned them but the classifier never visited them, so `Figure 1: allowed highway speed` was right-aligned. They are in `BLOCK_SELECTOR` and in both `.qrt-fa`/`.qrt-en` override lists now; `caption` and the cells stay out **on purpose**, because the tables switch owns table furniture, not the language detector. The line-height stamp and the stylesheet were made one list (1.7.0): the CSS puts `line-height: var(--qrt-leading) !important` on `caption`/`figcaption`/`summary` but `LEAD_SELECTOR` did not include them — and it is the inline stamp that beats Qoder's own `!important`, so those three elements stayed at 24px while the rest of the message followed the slider, i.e. the same "half-working slider" symptom as before. A source check now compares the two lists element by element rather than checking each in isolation, and the dead `[data-chat-composer][contenteditable]` selector was dropped: it matched nothing on the real DOM, since the composer container is not the editor. A window that never answers is no longer missing from `--check` (1.7.0): when `Page.enable` timed out the session was simply deleted, so that target did not even appear in the page-target count — a run that patched 1 of 2 windows looked exactly like a run against a single-window app. It now stays in `skipped`, gets its own report line reading `NOT PATCHED` with the reason, is counted, and a hint says a watching injector retries it every 15 s (`retrySkipped`). That retry path is established by source checks only — nothing has yet watched a real unanswered target answer on the second attempt. And the tool's own text was corrected (1.7.0): `live.js`'s console output and `index.js`'s closing hints still advertised «the «ا» button at the top-right», two batches after the trigger became a bottom-right SVG icon; a source check now refuses either string in those two files. **Two more defects were of the same family, and neither one is visible in the text of a rule: the declarations were correct, their position in the cascade was not (1.8.0).** The code-size slider used to *declare* `font-size: calc(1em * var(--qrt-code-scale))`; measured on the live window, an inline `<code>` computes `12px` inside a `13px` `<p>`, and the `font-family` from that very rule block reached the element only because it carries `!important` — the plain `font-size` beside it never did, so the slider moved nothing while its own stylesheet looked right. It now *scales* instead: `zoom: var(--qrt-code-scale)` on the code islands, which multiplies whatever size the app chose and leaves it untouched at 0 (`.monaco-editor`/`.cm-editor`/`.xterm` are excluded on purpose; they measure pixels for their own layout). And the runtime's `#qoder-rtl-vars` sheet declared the same custom properties as `rtl.css` does on `:root`, so **whichever sheet sits later in `<head>` won** — an order the self-heal itself breaks: when the app drops only `<style data-qoder-rtl>`, the repair re-appends it at the end of `<head>`, behind the vars sheet, and the stylesheet's defaults silently replace your numbers for the rest of the session (measured on the fixture after one repair: `{zoom:"1", face:"Vazirmatn QRT, Segoe "}`). Every declaration in the vars sheet is `!important` now, so winning does not depend on where the node happens to be. Qoder also puts Tailwind-style utilities on the prose elements themselves (`p.my-0.text-sm.leading-6.text-text`, plus a font on `.markdown-body`), so the three rules that must win — font stack, line-height and the text-size `zoom` — are repeated on those elements with `!important`; a container-only rule never reached the text, which is why two sliders looked dead. Its own chat font-size setting then pins `line-height:24px !important` with a four-class selector, which no injected sheet can out-specify honestly, so the runtime stamps the leading inline on the prose nodes (`data-qrt-lead` guards the work, `dispose()` removes every stamp). Typography is deliberately **not** gated on the direction switch: with it gated, Qoder's 24px pin took the paragraphs back while list items kept ours, so one message showed two rhythms — the sliders beside it (`zoom`) never stopped, which is what made it look like a random failure. **The message you typed is patched as an element, not by descent (1.8.1):** Qoder renders the human turn as one `whitespace-pre-wrap` div with no `<p>` inside it, so the bubble itself now carries the direction, the font stack, the leading stamp and its `.qrt-fa`/`.qrt-en` verdict — before that the replies followed the patch while your own message stayed in the app's left-aligned default. In the CDP route nothing is written to disk, so the Vazirmatn bytes ride inside the payload and are registered with `new FontFace(family, Uint8Array)` — that path performs no font fetch, so no `font-src` policy can refuse it (a `data:` URL font does fail under `font-src 'self'`; the fixture CSP proves it). The injected script uses no `eval`, so it stays compatible with `script-src 'self'`.

**Use:** `npx qoder-persian-rtl` — Node.js is the only prerequisite, and the CDP route installs no dependencies at all (`@electron/asar` moved to `devDependencies`; only the archive route needs it, so what is downloaded is the package itself — **201.6 kB** measured with `npm pack --dry-run` at 1.10.0 (388.9 kB unpacked, and the base64 font inlined in the payload is most of that) — not 6.8 MB of `node_modules`). If 9222 is already taken on your machine, `export QODER_RTL_PORT=9333` once and every command uses it; `--port` still wins over the environment. `qoder-rtl` wraps `live.js` as a child process and forwards its exit code, so `start` (also the no-argument default), `check`, `diagnose`, `list`, `status`, `launcher` and `remove-launcher` map onto the same engine, and `node cli.js check` is exactly `qoder-rtl check`. `status` is read-only and reports tool version, payload version, Qoder version, **what the debug port actually reports rather than "open/closed"** (serving DevTools / free / held by a process that is running / held by a PID that has already exited, i.e. an orphan socket that no new Qoder can bind), whether a launcher exists, and whether the archive route is even available on that machine. `start` will not launch Qoder on top of a port something already holds — it says who holds it and exits instead. The double-click `Qoder-RTL.cmd` is now **opt-in** (`qoder-rtl launcher`) rather than the advertised first step, and `qoder-rtl remove-launcher` deletes only the files this tool wrote. The route that rewrites the install is `patch --yes`; without `--yes` it prints why not to run it on Qoder 0.3.3 instead of touching anything, and no command in this tool ever kills a running Qoder. Requiring the package is inert too: `main` points at `live.js`, which used to self-boot an injector on `require()`, and that is now behind `require.main === module`. Then audit with `node live.js --check` (fourteen PASS/FAIL lines plus hints, logged to `%LOCALAPPDATA%\qoder-persian-rtl\cdp-test.log`) and `node live.js --diagnose` for a read-only look at what the live window actually computed. Two of those lines are functional probes: one briefly drives `lineHeight`/`chatSize` through the same `apply()` the panel uses and re-measures a real message, the other drives `codeSize` **alone** — from the user's own values, because `chatSize` scales the whole subtree through `zoom` and inline code with it, so driving both together would have greened a dead slider — and re-measures the `<code>` box's rect; both restore your values afterwards, and a line that reports `config NOT restored` says the probe's cleanup failed. The code line reads UNSURE rather than PASS when the conversation renders no inline `<code>` at all: a feature that could not be measured is not reported as working. A fourteenth line scores **your own messages** (the human bubble) rather than the replies, and follows the same rule — `UNSURE` with the name "no user message rendered to measure" when the conversation happens to hold no user turn. Keep the injector console open; closing it (or Qoder) removes the patch — and on this build the debug port has twice stopped listening shortly after attaching while the app restarted itself without the flag, so re-run the injector after every Qoder start. (It is not constant: in the 1.5.0 session the same port answered every request for over 45 minutes and across four separate injections.)
